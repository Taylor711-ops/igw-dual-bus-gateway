## 顺序与验收门槛

1. **先验收 R13 多节点**：主机编译、从机应用升级、两逻辑节点自动验收、密文认证后冻结候选。暂不改主机 BOOT。若失败，先保留结果并回到 R12.2，不带问题叠加功能。
2. **补 PL CAN 并行解析缺口**：已有 R2 完整工程可使用 can0_rx_in 做只读旁路。需实现并仿真标准帧采样、位填充移除、CRC/格式检查、时间戳及 AXI 帧邮箱；保留现有 PS CAN 的发送/ACK 路径。旁路只统计边沿不算 CAN 协议解析。编译布局布线和板端对照通过后才能计入 PL 功能。
3. **稳定性和报告与 RTL 工作交错进行**：候选冻结后启动 2 小时采集，保留客户端接收、板端计数、故障时间、NPU 数值检查和归档 SHA。未更改的旧版长测可作历史基线，不能替代新版本验收。
4. **再做选定高级项**：异构融合先定义设备/来源/时序契约；PL 无损打包压缩先建立 CPU 解包参考、压缩不利时原样回退，再实测内容一致性与实际字节比例；预测先取得可追溯的故障前序列并定预测时距，数据不具备时如实标“诊断演示”，不报预测准确率。
