# R26：主从双向数值演示（待板上验证）

本包在现有 R17.1 监控页面上增加“主机 → 从机”和“从机 → 主机”两个操作区。主机可以通过 CAN 或 RS485 写一个 16 位整数，从机也可以通过这两条总线将 16 位整数上报给主机。上报区由网页先通过 CAN 配置从机的值，然后从机周期性发送，主机收到新数据后才显示成功。RS485 上报需要 CAN 协调时隙；从机上报不是从机本地按键直接输入。选中“恢复自动计数”结束固定数值的周期上报。设置和普通寄存器都是易失的；重启从机后恢复自动计数。

数值范围 0–65535，并非文字或文件传输。两个逻辑设备运行在同一块从机板上；各自的寄存器独立。设备 1 的 NPU 分析能力和分类验证状态保持原样。文件演示仍使用已有文件服务，和监控服务不能同时启动。R26 从机源基于 R24，保留独立 SD 文件服务和 230400 文件传输配置；此兼容性仅通过本地模拟，尚需实板确认。请勿格式化或替换从机 SD 卡。

## 一、编译主机程序（Ubuntu 虚拟机）

解压整个目录到 `~/IGW_R26_BIDIRECTIONAL_DEMO`，在虚拟机终端逐条执行：

```sh
cd ~/IGW_R26_BIDIRECTIONAL_DEMO
sha256sum -c SOURCE_SHA256SUMS.txt
bash build.sh
```

需使用先前的 AArch64 Linux 交叉编译工具链。此包只含源代码，本地环境没有该工具链，尚未进行目标编译。编译成功后，将整个 `deploy` 文件夹中的文件复制至主机 SD 卡 `igw_apps/r26_bidir_install/`。保留原 `igw_apps/r17_1_rs485_uplink/` 和 `r24_rs230_experiment/`。

## 二、编译从机程序（Windows SDK）

1. 先备份现用 R24 从机工程的 `main.c` 及可恢复的 R24 启动/应用镜像，备份放在不会自动编译的目录。
2. 把本包 `slave_r26/slave/main.c` 复制为原从机 SDK 工程的 `main.c`，沿用已验证的工程配置和链接脚本，Clean / Rebuild，再按原流程烧录从机应用。不要修改主机的 BOOT.bin、设备树或 PL 位流，也不要重新初始化从机 SD 卡。
3. 保持从机独立 SD 卡插入。启动串口应看到 `[SD-R23] MOUNT=PASS`、`[FILE-R24-EXPERIMENT]` 和 `[BIDIR-R26]`。若 SD 挂载失败或 R26 标记缺失，先排查，不继续演示。R26 及文件服务均未经过这次实板验证。

## 三、主机安装与启动

先在正在运行的监控或文件服务的原终端按 Ctrl+C，等待完全退出。主机 Linux 终端执行：

```sh
/etc/init.d/S95igw_gateway stop
cd /mnt/mmcblk0p1/igw_apps/r26_bidir_install
sha256sum -c SHA256SUMS.txt
sh install_on_board.sh
```

安装脚本只生成独立的 `/mnt/mmcblk0p1/igw_apps/r26_bidir_demo`，不覆盖 R17.1；如目录已存在会停止，不要手动覆盖。安装成功后：

```sh
cd /mnt/mmcblk0p1/igw_apps/r26_bidir_demo
sh run_secure_gateway.sh
```

输入原私有密码（不要贴到聊天），等待 `R26 BIDIRECTIONAL DEMO ... READY`，保持这个终端运行。电脑打开 `http://192.168.31.222:8080`，关闭旧 UDP 面板，选择设备 1，确认 CAN 和 RS485 在线。服务默认最多运行 600 秒；比赛展示不要求两小时测试。退出时在主机服务终端按 Ctrl+C，等待归档和停止提示。

## 四、短演示与判断

1. 主机→从机：CAN，寄存器 16，值 12345，点击“主机发送并确认”。显示写入和独立读回通过，才算完成。如果已经是同一个值，会明确显示没有发送新写命令。然后可以换 RS485 和不同的数值再做一次。
2. 从机→主机：CAN，输入 54321，点击“配置并等待从机上报”；观察页面显示“从机真实上报已由主机接收”、接收序号和数量。切换 RS485，输入 2468，重复；这里使用 CAN 配置与时隙协调，但数据上报经过 RS485。
3. 设备切换为 2，用不同数值重复一组；两个逻辑节点位于同一物理从机板。点击“恢复自动计数”结束选中总线的固定值上报。若值相同、出现 REVIEW、超时或设备版本不匹配，保留显示和日志，不盲目重复操作。
4. 结束后检查 `devmem 0x8040000C 32`，期望 `0x00000000`。如需文件演示，先停止监控，确认退出后再启动既有文件服务。避免两个服务同时占用总线。

启动或测试不成功时，保留报错。可恢复备份的 R24 从机应用并启动原 R17.1 主机程序。CAN 线上曾出现错误和失败，不应把本地模拟的通过当作竞赛现场可靠性结论。

## 验证范围

本包在电脑上用真实从机调度器的模拟、FatFs RAM 盘和 DOM/fetch 模拟做过检查；真实 ARM 编译/链接、目标板收发、真实浏览器页面和 NPU 推理均待验证。旧版本目录 `slave_r17` 和部分测试为历史基线，只供回归测试，不是 R26 从机烧录文件。若目录内存在旧版本验证报告，仅作历史参考。
