# Source and validation boundary

- Vendor Zynq BD source `zynq/vendor/system_bd.tcl` was extracted from the user's `16_can_key_led.zip`, SHA-256 `7b67ad7620eedb197c5077fc3c5e60c73afb2262c2f723648880d62c3a403a13`. It provides the exact board DDR, PS SD0, UART0 and GPIO configuration. The new script enables PS UART1 EMIO and disables CAN0.
- `zynq/rtl/rs485_key_led.v` and `igw_uart_8e1.v` are unchanged from the previously user-tested `IGW_ZYNQ_RS4853_UPLINK.zip`, SHA-256 `d003e444dc9143cb0422553412b3f6c656c4a18242d8b9fe3e4e65d339304902`. The new top and guard share the UART with the PS file service; this combined image has not yet been validated on the device.
- The SD generation store, SHA-256 and RSF file protocol derive from `IGW_R23_SD_FILES.zip`, SHA-256 `d155c4790fedf4a604ff641b3d2e31be10a073749aa4f6a420d0e8f9f6dc1918`. Drive 0, an independent `IGW3` owner marker and unit 3 are used on Zynq. The file web derives from `IGW_R26_UI_REFRESH.zip`, SHA-256 `eddd5f3e6b79d1b5371e042cddba492b26412b55f58e08987622fe210535da92`.
- `run_local_checks.sh` passed locally: a FatFs RAM/mapped-disk fixture, actual C file protocol with simulated transport (including 1 MiB unit 3), actual file HTTP handler with fake backend, frontend DOM, device 1/2 simulated transport, and temporary-directory installer. These tests do not exercise actual serial timing or physical media.
- `zynq/src/main.c` passed native GCC syntax checking against the user's extracted Xilinx 2020.2 UART/standalone BSP headers with UART1 device ID supplied for checking. `file_engine.c` separately passed native GCC syntax checking against the extracted Xilinx `xilffs_v4_4` R0.13b and standalone BSP headers. Neither is an ARM cross-build or a link check against the new hardware platform.
- No Vivado, XSim, Vitis target compiler, board, TF card or target runtime was available in this environment. Gate RTL, PS/PL integration, timing, 9600 serial signal integrity, host AArch64 build, SD persistence and physical bus behaviour remain to be checked by the user. No 50 ms, zero loss, power-cut atomicity or multi-file concurrency claim is made.
