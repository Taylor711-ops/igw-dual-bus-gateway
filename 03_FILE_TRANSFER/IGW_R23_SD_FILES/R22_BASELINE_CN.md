# R22 文件传输阶段记录（2026-10-27）

当前文件子系统完成了命令行提速、容量扩展、网页操作及两条总线的中断恢复验证。硬件是一个 Linux 网关、一块从机板和一台笔记本；从机中的设备1/2是两个逻辑地址，不能描述为两块物理从机。

| 检查项 | 已观察结果 | 边界 |
|---|---|---|
| CAN 分块双向文件 | 4KiB、64KiB、1MiB 通过 | 正常测试日志零链路/应用包重试 |
| CAN 容量 | 设备2生成并取回4MiB通过 | 397.952秒，10539.7B/s；未覆盖4MiB PUT与全部总线矩阵 |
| RS485 分块双向文件 | R20已验证1MiB；R21.1的4KiB回归通过；R22网页1MiB取回通过 | 115200bit/s，1MiB约7.29kB/s来自R20CLI实测 |
| CAN与RS485访问同一文件 | 网页4KiB双向交叉读写、1MiB CAN写RS485读通过 | 每次只执行一个传输任务 |
| 逻辑设备隔离 | 设备2写17字节新内容，设备1仍为4096字节原内容 | 截图证据，具体哈希见JSON |
| 电脑完整文件 | Windows certutil与1MiB原文件SHA256一致 | 以太网浏览器下载到笔记本已校验 |
| CAN取回中断与重连 | 中断失败并锁定，重连后原1MiB文件完整取回 | 从头重传，不是断点续传 |
| RS485取回中断与重连 | 中断失败并锁定，重连后原1MiB文件完整取回 | 从头重传，不是断点续传 |
| 日志保存 | 各轮退出显示EVIDENCE_SAVED=1 | 主机SD证据保存，不代表从机文件掉电保存 |

重要限制：当前从机单文件槽在新PUT开始时就撤销旧文件的有效标记。因此PUT中断后的GET返回code8（没有有效文件）是当前实现行为，旧文件不会保留。未来持久化方案必须把“数据已写到介质”和“文件完成提交”分开，并在失败时保留最后一个已确认版本。

各轮原始证据仍在用户主机SD卡，路径及任务ID列在R22_BOARD_BASELINE.json。本记录依据对话中用户提供的输出，不把故障窗口的CAN错误计数写成正常窗口零错误，也不把网页结果概括成整个项目或高级评分全部完成。

当前已做到网页通过以太网接入网关，再经CAN/RS485交换文件。尚未完成：从机SD持久文件、超过4MiB的端到端传输、持久断点续传、高速以太网服务器文件交换、PL硬件压缩。NPU已实现的通信故障分类与未来设备故障预测应分开描述。
