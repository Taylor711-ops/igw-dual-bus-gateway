# 智联双总线工业协议融合网关：精简源码

本包只整理主机网关、两块物理从机及两个网页的项目源码、必要工程配置和生成脚本。没有加入历史整包、测试记录、日志、固件镜像或外部 SDK。

| 目录 | 内容 |
| --- | --- |
| `01_gateway_host/PL/` | 安路 DR1M90 主机 PL 逻辑、TD 工程配置与约束。 |
| `01_gateway_host/PS/monitor/` | 主机 CAN、RS485、上报、网页服务、加密归档、PL 采集和 NPU 程序及启动脚本。 |
| `01_gateway_host/PS/file_transfer/` | 主机 CAN／RS485 文件服务和文件网页后端。 |
| `02_slave_anlogic/` | 安路从机应用源码；同一块从机提供逻辑设备 1、2。 |
| `03_slave_zynq/` | Zynq-7020 从机 PL、Vitis PS、SD 文件服务及 Vivado 工程脚本。该板是逻辑设备 3，仅接 RS485。 |
| `04_web/` | 监控网页、文件传输网页及嵌入网页代码生成脚本。 |

## 源码版本

- 监控主机采用设备 3 的 RS485 上报扩展版本；CAN 接收、上报、加密归档和 NPU 源码来自其匹配的主机基线。网页是对应的设备 3 监控网页。
- 文件主机采用 **CAN 设备 1 与 RS485 设备 3** 定向并行版。两条总线的该组合曾完成 65536 字节文件下发及读回校验。其他组合不因此自动具备并行能力。
- 安路从机 `R26_monitor_and_file` 与 `R23_file_compatibility` 是**同一块板的两个可选软件版本**，不是额外从机；前者包含 R26 数值上报与文件服务，后者保留 R23 文件服务版本。按现场已烧录版本和要展示的功能选择，不要将两个 `main.c` 同时放进一个工程。
- Zynq 文件工程中的 PL 数值通路和 PS 文件服务共同组成该板的代码；其 `sim/` 是 Vivado 工程脚本直接引用的仿真源码。

## 工具与使用

1. 主机 PL 工程入口：`01_gateway_host/PL/soc_prj/soc_prj.al`。工程引用的安路厂商生成 IP、设备包和 SDK 未包含在本源码包内，需要使用有权使用的原工程或安路工具恢复；因此不能仅凭本包保证 TD 工程直接综合。
2. 主机 PS：在具备 AArch64 Linux 交叉编译器的 Ubuntu 环境运行 `bash 01_gateway_host/PS/build_components.sh`。NPU 可执行文件还需要设置 `IGW_ARMNN_ROOT` 指向包含 `include/armnn` 和 `lib/libarmnn.so` 的 SDK。该脚本只编译源码，不是完整的板端安装包；现有启动脚本依赖对应的板端目录、运行库和校验文件。
3. 安路从机：在选定版本下，`slave/main.c` 是由同目录 `generate_slave.py` 和 `slave_src/` 生成的单文件应用；需要原安路 SDK、BSP、FatFs 和板卡工程。保留原链接脚本及板卡配置。
4. Zynq 从机：Vivado/Vitis 2020.2 使用 `03_slave_zynq/create_project.tcl` 创建工程，`src/` 是 Vitis 应用，平台须启用 `xilffs`。原板卡的 PS 配置、SDK 和工具不在本包。
5. 修改 `04_web/` 的 HTML 后，在源码根目录执行 `python3 04_web/generate_embedded.py`，更新对应后端所用的嵌入式网页头文件。

监控服务与文件服务共用主机硬件资源，按原现场流程切换。文件任务中的 CAN 设备 1 与 RS485 设备 3 可以按指定组合并行；RS485 上的多个节点共享一条半双工总线。
