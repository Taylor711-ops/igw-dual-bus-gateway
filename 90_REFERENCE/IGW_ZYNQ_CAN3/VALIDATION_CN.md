# 验证记录

执行于本工作环境，均为 Linux x86_64 仿真，不是 ARM 目标构建或实板证据：

1. ZYNQ `main.c` 使用用户 CAN 工程 BSP 的 68 个头文件做 GCC 语法检查（宿主编译器，未链接、未生成 ARM ELF）。
2. 针对实际 ZYNQ 应用 `handle_one()`，使用虚拟 XCanPs 驱动检查帧字节/ID、读写、写重复去重、拒绝其他 ID、CAN 上报会话与确认。
3. 网关 HTTP/UDP 后端及共享设备寄存器使用原生产 C 代码、UNIX socket 模拟 CAN/RS485/MMIO，设备 3 使用本包 ZYNQ 实际处理函数；验证设备 3 CAN 读写成功、没有设备 3 的 RS485 轮询、服务端拒绝设备 3 的 RS485 和 CROSS、设备 1/2 交叉验证成功。
4. 原主机 CAN 上报守护进程与 ZYNQ 实际上报状态机通过本地虚拟帧验证握手和确认，主机接收数量增加并收到 54321。
5. 浏览器 DOM/fetch stub 验证设备 3 的 RS485“未接入”、按钮禁用、切换设备 1 后恢复。并运行原 R26 页面逻辑回归。
6. 主机 Web C 通过本地 GCC 编译，shell 脚本语法检查通过。安装器在临时目录验证了副本、校验清单、原目录保留和重复安装拒绝；挂载检查及进程锁检查在模拟中替换，仍需板端验证。

`run_local_checks.sh` 可在具有 GCC、Python3、Node 和 ASan/UBSan 的 Linux 环境重新执行模拟。真实硬件的时钟、引脚、电平、总线仲裁、持续稳定性、上报和网页结果均待实测；不构成中级验收通过声明。
